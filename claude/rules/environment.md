# Environment

- macOS, Bash shell. Shell config is user-managed and not tracked in dotfiles. Machine-local non-secret vars (GCP project, aliases) go in `~/.bashrc.local`, which is not tracked in git. `web-verify` is available via `export PATH="$HOME/anaiis-dotfiles/bin:$PATH"` in shell config. Never modify `.zshrc`.
- `direnv` manages per-project env vars via `.envrc`, loads automatically on cd.
- Secrets are never stored in JSON settings files and never globally exported from shell config. They live in one of three tiers: (1) the CLI's own credential store (`gh auth login`, `coderabbit auth login`, `postman login`); (2) cross-project env vars in `~/.config/secrets/global.env` (chmod 600), loaded only by projects whose `.envrc` includes `dotenv ~/.config/secrets/global.env`; (3) project-specific vars in that project's `.envrc`. Claude uses a secret only when the user names the variable; permission deny rules and the bash-guard hook block reading or dumping them.
- `uv` manages Python versions. Check `.python-version` before assuming the Python version.
- To delete a disposable path (`.ruff_cache`, `.venv`, `node_modules`, `__pycache__`, `dist`), issue `rm -rf <path>` as its own standalone Bash call. This is the simplest form, and `bash-guard.sh` allows it.
- If a command holds a recursive `rm` and a shell operator, `bash-guard.sh` allows it only when every statement is on a short vetted list. The list holds `rm`, `mkdir`, `cd`, `ls`, `echo`, `printf`, `pwd`, `true`, `false`, `test`, `[`, `basename`, `dirname`, literal assignments, and `for NAME in <literal words>` loops. Runners (`uv`, `make`, `python`, and similar) are not on the list. A child program of a runner can delete or create a path outside the guard. After a pipe, only `grep`, `head`, `tail`, `wc`, `cut`, `tr`, `basename`, and `dirname` are allowed. The statements join with `;`, `&&`, `||`, a newline, or a pipe.
- For an allowed compound command, the hook runs `rm` and `mkdir` through `claude/hooks/safe-rm.sh`. The first use of each version of that file asks once. The rewritten command then writes a marker file, and later runs of that version do not prompt. If the harness does not apply the rewrite, no marker appears and every run asks. The script checks each expanded path. The roots are the session scratchpad, a disposable folder inside the working directory, `tests/fixtures/`, `tmp/` (except `tmp/worktrees`), and a `tmp.*` folder under `$TMPDIR`. Both `rm` and `mkdir` use these roots and change nothing else. `mkdir` allows only the flags `-p` and `-v`. The working-directory roots are off when the working directory is `$HOME`, a parent of `$HOME`, or `/`. It never deletes or creates `/`, `$HOME`, the working directory or a parent of it, or a path with a `.git` component. If one path is refused, it deletes or creates none, and the whole command stops: later statements do not run.
- If the hook asks for confirmation, or `rm` prints `safe-rm: refused`, do not rewrite the command to avoid the check. Run the delete as its own call with a literal path. A deletion word in any position of any statement makes the command ask: `rm` after the first word, `rmdir`, `find`, `xargs`, `eval`, `bash`, `sh`, `git`, `mv`, and similar. These also ask: a redirect to a file, `$(...)`, a backtick, `/bin/rm`, and `command rm`. A glob or single-quoted operand of `rm` asks. A loop variable or `printf -v` that names a guard variable asks.
- When working in projects with worktrees, confirm which worktree/directory you're in before running commands.
- Any hook or script that computes the repo root from its own path must resolve `BASH_SOURCE[0]` through `realpath` before the `dirname`/`cd` walk. `~/.claude/hooks/` and `~/.claude/scripts/` are always symlink layers into the repo; without `realpath`, the walk lands at `~/` instead of the repo root. Pattern: `SCRIPT_REAL="$(realpath "${BASH_SOURCE[0]}")"; REPO_DIR="$(cd "$(dirname "$SCRIPT_REAL")/../.." && pwd)"`.
